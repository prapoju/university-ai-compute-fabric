## 1. Security

Threats covered: unconfirmed execution of a destructive request, token forgery and reuse,
secrets in the audit trail, and fabricated or injected facts in prose.

- **Confirmation token (AD-4, AD-5).** Gate tokens are generated by the contract format
  `gt-[0-9a-f]{32}` and are unique per start.
  - `tests/unit/test_token_idgen.py::test_every_token_has_the_contract_shape_and_is_unique`
  - `tests/unit/test_token_idgen.py::test_two_generators_never_issue_the_same_first_token`
  - `tests/atdd/test_story_2_2.py::test_the_real_app_issues_a_different_token_on_every_start`
  - Wrong token is refused and the proposal stays in dry-run:
    `tests/atdd/test_story_2_3.py::test_a_wrong_token_is_forbidden_and_the_proposal_stays_in_dry_run`,
    `tests/atdd/test_story_2_3.py::test_another_proposals_token_is_forbidden`.
  - A token lapses one lifetime after issue; the lifetime is 60 s and configurable (Annex adaptation "Token lifetime", `docs/impl2-rules.md`):
    `tests/unit/test_confirmation.py::test_the_token_is_fresh_up_to_and_including_the_lifetime`,
    `tests/unit/test_config.py::test_the_gate_token_lifetime_defaults_to_sixty_seconds_and_is_overridable`,
    `tests/atdd/test_story_2_3.py::test_the_token_is_accepted_up_to_sixty_seconds_and_not_after`.
- **Token never in the audit.** `tests/api/test_dry_run_route.py::test_the_dry_run_audit_never_holds_the_token_or_the_query`.
- **Secrets redacted before storage.**
  - `tests/unit/test_redaction.py::test_every_secret_key_pattern_is_redacted_case_insensitively`
  - `tests/unit/test_redaction.py::test_a_secret_key_hides_a_structured_value_too`
  - `tests/unit/test_audit_writer.py::test_both_summaries_are_redacted`
  - `tests/atdd/test_story_1_5.py::test_secrets_in_the_query_never_reach_the_audit_tables`
  - `tests/atdd/test_story_1_5.py::test_a_secret_that_reaches_a_port_parameter_is_redacted_before_it_is_stored`
- **Rejections leave no token in logs.** `tests/unit/test_confirmation_service.py::test_a_rejected_confirmation_logs_its_id_and_code_and_never_a_token`.
- **Prompt injection does not lift a refusal.** `tests/atdd/test_story_2_1.py::test_injected_confirmation_text_does_not_lift_the_refusal`.
- **No fabricated facts (AD-2, AD-8).** `tests/unit/test_node_triage_handler.py::test_a_provider_failure_aborts_the_turn_and_never_fabricates_steps`,
  `tests/unit/test_diagnosis.py::test_the_fact_tokens_cover_everything_prose_must_not_say`,
  `tests/unit/test_citations.py::test_is_bound_needs_every_claim_cited_and_every_citation_present`.

**Status: PASS.** Every security rule above has at least one test that fails if the rule breaks.
The red-phase logs for the Flow A stories are `docs/evidence/impl2/red-2-1.log` to `red-2-4.log`.

## 2. Concurrency

Hazards: double allocation of a proposal, two dispatches of the same proposal, and session or
fan-out state shared between operators.

- **Atomic claim, one winner.** Proposal store, real SQLite:
  `tests/integration/test_proposal_store.py::test_fifty_simultaneous_claims_have_one_winner`,
  `tests/integration/test_proposal_store.py::test_fifty_simultaneous_dispatch_claims_have_one_winner`,
  `tests/integration/test_proposal_store.py::test_a_token_confirms_at_most_one_proposal`.
- **Identical confirm raced with a different one never transitions twice.**
  `tests/atdd/test_story_2_3.py::test_an_identical_confirm_raced_with_one_that_has_another_token_never_transitions_twice`.
- **Fifty concurrent dry-runs, fifty unique tokens, no server error.**
  `tests/atdd/test_story_2_2.py::test_fifty_concurrent_dry_runs_give_fifty_unique_tokens_and_no_server_error`.
- **Fifty operators released together, cited answers, no lock errors (story 1.6 ATDD).**
  `tests/atdd/test_story_1_6.py::test_fifty_operators_released_together_get_cited_answers_and_no_lock_errors`.
- **Parallel operators keep their sessions apart.** `tests/integration/test_sessions_concurrency.py::test_parallel_operators_keep_their_sessions_apart`.
- **Lanes settle in argument order whatever the completion order.**
  `tests/unit/test_parallel_reads.py::test_recorded_calls_settle_in_argument_order_when_the_second_read_finishes_first`,
  `tests/atdd/test_story_1_6.py::test_the_audit_lists_the_tool_calls_in_argument_order_whatever_the_completion_order`.
- **Recorder is required, so audit rows cannot be dropped silently (story 1.6 hardening, commit `cafd942`).**
  `tests/unit/test_parallel_reads.py::test_a_fan_out_cannot_be_built_without_its_recorder`.

**Status: PASS.** The 50-operator cases are real SQLite and real app paths. No test in this
dimension uses `sleep`; gates are `threading.Event` barriers.

## 4. Resilience (typed failures, no crash)

Rule: a provider or executor failure is a typed result (AD-12), never a 500 and never a partial
answer.

- **Typed 503 `PROVIDER_UNAVAILABLE` with a read still running at the budget.**
  `tests/unit/test_parallel_reads.py::test_one_slow_read_of_two_is_a_503_at_the_budget_and_its_late_result_is_dropped`,
  `tests/atdd/test_story_1_6.py::test_a_read_still_running_at_the_budget_is_a_503_and_records_nothing_afterwards`.
- **A read that raises is a typed failure; both raising is one typed 503.**
  `tests/unit/test_parallel_reads.py::test_a_read_that_raises_is_a_typed_failure_not_an_exception`,
  `tests/atdd/test_story_1_6.py::test_both_reads_that_raise_are_one_typed_503`.
- **Broken database answers 503 and never crashes.** `tests/api/test_evidence_api.py::test_a_broken_database_answers_503_on_both_routes_and_never_crashes`,
  `tests/api/test_audit_api.py::test_a_broken_audit_table_is_a_503_not_a_crash`.
- **Executor unavailable is typed and never retried.**
  `tests/unit/test_proposal_dispatcher.py` (`EXECUTOR_UNAVAILABLE` asserted, one call only),
  `tests/atdd/test_story_2_4.py` (`EXECUTOR_UNAVAILABLE` at the route),
  `tests/api/test_proposal_routes.py` (`EXECUTOR_UNAVAILABLE` on the proposal route).
- **Duplicate apply is refused, not repeated.** `tests/unit/test_execution.py` (`EXECUTOR_DUPLICATE_APPLY`),
  `tests/atdd/test_story_2_4.py` (409 with `EXECUTOR_DUPLICATE_APPLY`).
- **Partial executor result fails the proposal.** `tests/atdd/test_story_2_4.py::test_a_partial_apply_is_failed_and_the_502_body_is_the_proposal`,
  `tests/integration/test_db_schema.py::test_partial_executor_result_must_fail`.
- **Provider failure during revalidation writes nothing.**
  `tests/unit/test_confirmation_service.py::test_a_provider_outage_during_revalidation_is_a_failure_and_writes_nothing`.
- **Prose outage recovers.** `tests/unit/test_prose_adapter.py::test_an_injected_failure_is_llm_unavailable_and_recovers`.

**Status: PASS.** Each failure path returns a catalog code and leaves no partial write.

**Cold start (NFR-7 part).** `tests/nfr/cold_start.py` starts uvicorn as `playwright.config.ts`
does and polls `/healthz` with a bounded deadline. The first 200 came at **0.54 s**, budget 60 s
(`docs/evidence/impl2/nfr7-cold-start.log`). The 8-hour 99 % window is waived (traceability section 8).
